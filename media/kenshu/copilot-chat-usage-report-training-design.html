定着と効果測定

Copilot Chat利用レポートを研修へ使う｜非ライセンス利用者の定着を測る

Copilot Chatの利用レポートは、ライセンスなしの利用者だけが対象で、入口・初回・反復の3つに分けて読みます。
利用レポートを見ても研修の改善につなげられない、研修担当や情シス、DX推進担当の方に向けた記事です。
対象の限定、数字の読み方、研修課題への翻訳、月次レビューの型が分かります。

Copilot Chatの利用レポートは、どう読んで研修につなげればよいですか？

対象はライセンスなしの利用者だけです。入口、初回、反復利用を分けて読み、数字を研修課題へ翻訳します。

Microsoft Copilot Chatの利用レポートは、対象が違います。Microsoft 365 Copilotの有償ライセンス保有者のレポートとは別物です。

研修担当者が最初に行うことは、Copilotライセンスを持たない利用者の入口、初回利用、反復利用を分けることです。そのうえで、業務シナリオへ接続します。

Microsoftの現行文書では、Copilot Chat usage reportの対象が決まっています。Copilotライセンスを持たない利用者の、Copilot Chat利用です[1]。有償ライセンス保有者の利用は、Microsoft Copilot usage reportで確認します[2]。

レポートには、次の項目が含まれます[1]。

  • active users
  • average daily active users
  • total prompts と平均prompt数
  • entry point別の利用

利用レポートは、どんな手順で研修に活かしますか？

対象を限定し、入口と反復を分け、数字を課題へ翻訳し、業務成果を併記して、月次で見直します。

  1. 対象を「ライセンスなし」に限定します。月次資料には、対象ライセンス、対象人数、期間、UTC基準、匿名化設定、反映遅延を記します。Copilot Chat activityは、日次終了後48時間程度遅れる場合があります[1]。研修直後の未反映を、不参加とみなしません。
  2. 入口と利用回数を分けます。Teams、Outlook、Edge、Copilotアプリ、Wordなどが入口です。入口ごとの差は、発見経路と業務配置の差として読みます。初回利用者が増えても、翌週に戻らなければ定着とはいえません。7日、28日、90日を同じ定義で追い、初回、複数日利用、複数週利用へ分けます。個人名の表示は既定で匿名化されます。必要性と権限を確認せず、解除しません。
  3. 数字を研修課題へ翻訳します。数字の状態ごとに、打ち手が違います。比較表にまとめます。Microsoft Adoptionの資料は、targeted trainingの設計を示しています[3]。利用強度やアプリ別利用から設計する考え方です。他社のleaderboardや閾値を自社KPIへコピーせず、対象業務と利用者の権限に合わせます。
  4. 利用増と業務成果を並べて見ます。研修前後で、対象業務の完了、原資料確認、差戻し、禁止情報入力、利用者の自己評価を併記します。Copilot Analyticsは、adoptionとimpactを分けて扱っています[4]。usage reportだけで、ROIを断定しません。
  5. 月次レビューを固定の表で回します。次の項目を固定表にします。対象人数、active users、日次平均、prompt数、入口、反復利用、対象業務、研修施策、次の一手です。数字が弱い場合も、追加研修に決めつけません。入口、権限、業務選定、上司支援を分けて診断します。

利用レポートの読み方で、うまくいかない例にはどんなものがありますか？

2つのレポートを足す、prompt数を成果とみなす、未取得の操作を未利用と決める、の3つが典型です。

  • 有償ライセンス保有者の利用と足して、全社利用率を作る。母集団と機能差が消えます。
  • 研修直後の未反映を、不参加とみなす。反映の遅れを考慮せずに判断します。
  • 初回利用の増加を、定着とみなす。たとえば、Teamsからの初回利用だけが増えた場合です。研修参加者が、案内された入口を試した可能性は確認できます。業務定着までは言えません。翌週も同じ対象者群が戻ったか、別の業務アプリへ広がったか、成果物の確認負荷が増えていないかを、追加で見ます。
  • prompt数を、品質や時間削減の証明とする。prompt数は活動量です。
  • 部門の順位を、prompt総数だけで決める。部門比較では人数差を残します。一人当たり利用と、対象業務の完了を並べて判断します。
  • 取得されない操作を、未利用と決める。ExcelやPowerPointの一部編集モードが、active usageへ含まれない場合があります。取得範囲は更新されます[1]。製品文書の更新日と管理画面を、再確認します。
  • 利用ログだけで、品質や生産性の因果を語る。利用ログだけでは、回答品質、生産性、従業員体験の因果を示せません。

製品仕様や対象レポートは変わります。Microsoft Learnの更新日を毎月確認し、ライセンス保有者向けのレポートと混同しないことが前提です。関連する有償ライセンス保有者レポートとは、別系列で報告します。

数字の状態ごとに、研修の打ち手はどう変わりますか？

見つけられない、初回で止まる、業務に結びつかないの3つで、改善する場所が違います。

数字の状態打ち手
対象者が、Copilot Chatを見つけられないpin設定や入口案内を改善する
初回promptで止まる検索、要約、下書きなど、安全な一業務を演習する
利用は続くが、業務へ結びつかない部門資料、確認責任、禁止データを含む、ロール別演習へ進む

よくある質問

Copilot Chatの利用レポートは誰の利用を対象にしていますか？

Copilotライセンスを持たない利用者のCopilot Chat利用が対象です。有償ライセンス保有者の利用は別のレポートで確認します。両者を足して全社利用率を作ると、母集団と機能差が消えます。

利用が増えたら研修は成功したと言えますか？

言えません。prompt数は活動量で、品質や時間削減の証明ではないからです。初回利用が増えても翌週に戻らなければ定着とは言えません。業務の完了や原資料の確認、差戻しも併せて見ます。

研修直後にレポートの数字が出ていないときはどう判断しますか？

不参加とはみなしません。Copilot Chatの活動は、日次の終了後48時間程度遅れて反映される場合があるためです。月次資料には対象期間や反映遅延も記載し、同じ定義で比べます。

次の一歩は何から始めればよいですか？

月次レビューの固定表を作り、対象人数や入口、反復利用などを、同じ定義で記録することから始めます。

  1. 対象ライセンス、対象人数、期間、UTC基準、反映遅延を、月次資料の冒頭に記します。
  2. active users、日次平均、prompt数、入口、反復利用を、固定表に入れます。
  3. 数字の状態ごとに、研修施策と次の一手を書き込みます。
