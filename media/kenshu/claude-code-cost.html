Claude Codeを法人で使う契約形態は何があるのか？

入口はTeamプラン・Enterpriseプラン・API従量の3つ。少人数はTeam、統制重視はEnterprise、自動化はAPIが基本線だ。

情シスの視点

Team・Enterprise・APIの3択という前提がそもそも間違っていた。

Claude Codeは、Anthropicが提供するターミナルで動くコーディングエージェントだ。法人で使う場合の契約は大きく3系統に分かれる。①Teamプラン（人数分のシート課金）、②Enterpriseプラン（シート料金と従量料金の組み合わせ）、③API従量課金（Claude Console経由、またはAmazon Bedrock / Google Cloud / Microsoft Foundryなどのクラウド経由）だ。用途が違えば併用もできる。個人向けのPro（月20ドルまたは年200ドル）やMax（月100ドルまたは200ドル）でもClaude Codeは使えるが、メンバー管理や一元請求といった法人向けの管理機能がない。会社として導入するならTeam以上を軸にする。以下はAnthropic公式のTeamプラン、Enterpriseプランの説明（2026年9月30日確認）にもとづく比較だ。

導入形態料金（米ドル）含まれるもの・特徴向いている組織
Team（Standardシート）1人月20ドル（年払い時）

Teamプランは2〜150席が対象で、StandardとPremiumを混在できる（2026年9月30日確認）。全員にPremiumを配る必要はない。利用量の多い人にPremium、それ以外はStandardを割り当てる。150席を超える場合や監査ログなどの統制要件がある場合はEnterpriseを検討する。

Teamプランで注意したいのは、StandardとPremiumのどちらにも利用枠があることだ。枠はメンバーごとに設定され、Claude、Claude Code、Coworkで共有される。枠を使い切った後も続ける場合は、管理者が使用量クレジットを有効にする。超過分はAPI標準料金で消費され、Teamでは組織全体と利用者ごとの月間支出上限を設定できる。Teamプランの料金は、シートに含まれる利用枠と、必要に応じた使用量クレジットの二段構えだ。

現行Enterpriseは、単一のEnterpriseシートを年払いで契約し、Claude、Claude Code、Coworkの全利用量をAPI標準料金で別途支払う。シート料金にトークン利用枠は含まれない。セルフサービスは20席以上で、利用量を前払いクレジットから消費する。営業経由は50席以上で、利用量を月次後払いする。旧契約のChat、Chat + Claude Code、Standard、Premiumシートは次回更新まで条件が残るが、更新時に現行の単一シートへ移行する。請求を比較するときは、管理画面に表示されるシート種別を確認してほしい。

API従量課金だと実際いくらかかるのか？

人数だけでは決まらない。モデル別の入出力単価と自社のトークン使用量を測り、月額と年額へ換算する。

経理の視点

従量課金は稟議に載せにくい。上限の置き方を先に決める必要がある。

API従量課金の月額は、人数だけでは見積もれない。使うモデル、入力と出力のトークン数、プロンプトキャッシュ、バッチ処理、データ所在地で変わるからだ。まず標準のモデル別単価を置き、2〜4週間の試験運用で利用者別の実額を測る。2026年9月30日に確認したAnthropic公式API料金は次のとおり。

モデル入力（100万トークンあたり）出力（100万トークンあたり）
Claude Fable 5.110ドル50ドル
Claude Opus 5.54ドル20ドル
Claude Sonnet 5.52ドル10ドル
Claude Haiku 4.51ドル5ドル

出典：Anthropic公式「Pricing」（2026年9月30日確認）。単位は米ドル／100万トークン。表は標準のベース入出力料金で、プロンプトキャッシュ、バッチ処理、データ所在地、Fast mode、クラウド事業者の料金は別条件。

コストの振れ幅を作るのはモデル選択とセッションの持ち方だ。Opusを常用し長いセッションを開きっぱなしにすれば膨らみ、Sonnet中心でこまめにコンテキストを切れば抑えられる。管理面では、Claude ConsoleにClaude Code専用のワークスペースが自動作成され、ワークスペース単位の支出上限（スペンドリミット）とメンバー別の利用レポート（Claude Code Analytics API）が使える。つまり「青天井になるのでは」という稟議上の懸念には、公式の上限機能で答えられる。Bedrock / Google Cloud / Microsoft Foundry経由の場合は各クラウドの請求・予算管理に乗るため、既存のクラウド予算枠で処理したい会社はこの経路も選択肢になる。

予算は、2〜4週間の試験運用で利用者別の実額を測り、「1人当たりの月間実測額×対象人数×12カ月」で年額へ換算する。モデル構成や利用量を変える場合は、同じ期間でもう一度測る。稟議には、公表された一律の月額目安より自社データを使う。

情シスの視点

TeamではStandardとPremiumを混在できる。人が使うシート料金と、自動処理のAPI利用料を分けて見積もると、利用者数と処理量のどちらで費用が増えるかを確認できる。

どの規模・体制ならどれを選ぶべきか？

2〜10人の試験導入はTeamで利用量に応じてStandardとPremiumを選ぶ。150人超やTeamを超える統制要件はEnterprise、CI/CD組み込みや自動化が主目的ならAPIを検討する。

プランの優劣ではなく、組織の状態との相性で決める。判断の起点は「誰が・何人で・何のために使うか」の3点だ。下の表に典型パターンを整理した。

状況・規模推奨理由
2〜10人でまず試したいTeam（利用量に応じてStandard/Premium）両シートにClaude Codeが含まれる。含有枠内の利用を試し、超過利用料も分けて見積もる
11〜150人へ展開したいTeam（Standard/Premium混在）職種だけで分けず、実際の利用量と必要な枠を見てシートを配分する
150人超・監査ログ／SCIM／カスタム保持などTeamを超える統制要件があるEnterprise必要な追加機能と契約条件を照合する。SSOはTeamにも含まれるため、SSOだけを切替理由にしない
CI/CD・自動化・社内エージェントに組み込みたいAPI従量（Console）人のシートでなく処理量に課金される。ワークスペースの支出上限で統制できる
既存のクラウド予算・契約で賄いたいBedrock / Google Cloud / Foundry経由自社クラウドの請求に合算され、調達・稟議の経路を新設しなくてよい
担当者が個人で検証したいPro / Max低コストで試せる。ただし法人管理機能はないため、本導入時にTeam以上へ移行する

迷いやすいのは「Teamシートか、API従量か」の分岐だ。判断軸は利用の性質にある。人が対話しながら使う日常利用はシート課金のほうが予算を立てやすく、夜間バッチやパイプラインなど機械的な利用は従量課金のほうが実態に合う。両者は併用できる。ただし、Claude CodeをTeamで使う端末に環境変数ANTHROPIC_API_KEYがあると、サブスクリプションよりAPIキーが優先され、API利用料として請求される。対話利用と自動処理で認証方式と実行環境を分ける。導入の具体的な進め方はClaude Codeの法人導入手順を、エンジニア以外の部門での使いどころは非エンジニアのClaude Code活用をあわせて参照してほしい。

ライセンス費以外に見落としやすいコストは何か？

ライセンス費より、運用・教育・ガバナンスの人件費が総コストを左右する。定着支援まで含めて予算化する。

経営企画の視点

ライセンス費だけ見て通した予算が、運用と教育で膨らむ——これが一番怖い。

稟議で最も多い失敗は、ライセンス費だけを積んで「導入したのに使われない」状態に陥ることだ。Claude Codeはインストールすれば動くが、組織として成果が出る状態にするには、ライセンス以外の投資が要る。総コストの内訳を先に見せておくほうが、稟議は通りやすく、導入後の失望も防げる。

費目中身備え
運用管理シートの棚卸し、支出上限の設定、利用状況のモニタリング管理者の担当時間を月数時間単位で確保。公式の支出レポート・分析APIを使う
教育・定着使い方研修、プロンプトや指示の型づくり、質問を受ける窓口導入研修と社内チャンピオンの育成をセットで計画する
ガバナンスデータ取り扱いルール、権限設計、監査ログの運用利用ガイドラインを先に整備し、扱ってよい情報の線引きを明文化する
コンテキスト整備リポジトリの整理、CLAUDE.md等の社内ナレッジの記述AIに渡す前提情報を整える工数を初期投資として見込む
従量の変動長いセッションや上位モデル常用による月次のブレ支出上限＋月次レビューで早期に検知する運用にする

ライセンス費は氷山の一角だ。水面下の運用・教育・ガバナンスまで予算化して初めて、稟議の数字は現実になる。

特に教育・定着は削られやすいが、ここを削ると利用率が伸びず、シート費だけが毎月出ていく最悪のパターンになる。展開時の運用ルールや教育設計はClaude Codeの社内展開で詳しく扱っている。外部の研修を使う場合は、ツール操作の説明で終わらず、自社の業務・コードベースに引きつけた演習まで踏み込むものを選ぶ。TechWorkerのClaude Code研修もこの設計で提供している。

経営企画の視点

稟議で詰まるのは金額ではなく根拠だった。少人数の実測値を先に取る——見積もりを立てる順序が逆だったと気づいた。

稟議に載せる費用対効果はどう組み立てるか？

捏造したROIでなく、パイロット実測×自社人件費の定性フレームで組む。再現可能なロジックが稟議を通す。

「開発生産性が◯倍」といった出所の曖昧な数値を稟議に貼るのはやめたほうがいい。決裁者が一度でも根拠を突くと、提案全体の信頼が崩れる。代わりに、自社で再現可能なロジックを組む。手順は4つだ。

  1. 対象業務を特定する。「開発全般」ではなく、コードレビュー・テスト作成・調査・定型改修など、誰のどの作業に効かせるかを絞る。
  2. パイロットで実測する。2〜4週間、対象業務の所要時間を導入前後で記録する。効果の数字はここからしか生まれない。
  3. 費用は総額で見せる。ライセンス費（または従量の実測単価×人数）＋運用・教育・ガバナンスの工数を年額換算する。
  4. 効果を自社の時給で金額に換算する。削減時間×自社人件費を主軸に、品質・リードタイム・属人化解消などの副次効果は定性で添える。他社の数値やベンダーの汎用ROIを主語にしない。

このロジックを稟議書に落とすときの構成要素をチェックリストにした。上から順に埋めれば、決裁者が確認したい論点をひととおりカバーできる。

稟議の構成要素チェックリスト

□ 目的とスコープ（対象部署・人数・期間）
□ プラン選定の根拠（Team/Enterprise/APIの比較と選定理由）
□ 費用の総額（ライセンス＋運用＋教育、年額換算。従量はモデル別単価と自社実測で算出）
□ 効果の測定方法（対象業務・実測の取り方・判定基準）
□ リスクと統制（データ取り扱い・権限・監査・支出上限）
□ 定着計画（研修・社内チャンピオン・展開ステップ）
□ 見直し条件（利用率や効果が基準未満のときの縮小・撤退ライン）

「見直し条件」まで書くのがコツだ。撤退ラインを先に示す提案は、推進者の希望的観測ではなく経営判断の材料として読まれる。先行企業がどの業務で成果を出しているかはClaude Code導入事例にまとめているので、対象業務を絞る際の参考にしてほしい。

よくある質問

Claude CodeはTeamプランのStandardシートでも使えますか？

使えます。Claude CodeはTeamの全シートに含まれ、PremiumはStandardより利用枠が大きいシートです。米国向け価格は、Standardが年払いで1人月20ドル、月払いで25ドル、Premiumが年払いで1人月100ドル、月払いで125ドルです。どちらにも利用枠があり、上限後も続ける場合は、管理者が使用量クレジットと支出上限を設定します。料金・通貨・税は地域によって異なるため、契約画面でも確認してください。

現行のEnterprise契約は定額ですか？

定額のシート料金だけではありません。新規Enterpriseは単一のEnterpriseシートを年払いで契約し、Claude、Claude Code、Coworkの利用量をAPI標準料金で別途支払います。シート料金にトークン利用枠は含まれません。セルフサービスは20席以上で利用量を前払いクレジットから消費し、営業経由は50席以上で利用量を月次請求します。旧契約のChat、Chat + Claude Code、Standard、Premiumシートは請求方式が異なるため、管理画面のシート種別を確認してください。

API従量課金は1人当たり月いくら見込めばよいですか？

人数だけでは決まりません。2026年9月30日に確認したAPI標準料金は、100万トークン当たり、Claude Fable 5.1が入力10ドル・出力50ドル、Claude Opus 5.5が入力4ドル・出力20ドル、Claude Sonnet 5.5が入力2ドル・出力10ドル、Claude Haiku 4.5が入力1ドル・出力5ドルです。モデル、入出力の長さ、キャッシュ、バッチ処理、データ所在地で請求額が変わります。2〜4週間の試験運用で利用者別の実額を測り、組織と利用者の支出上限を設定してから年額予算へ換算してください。

TeamとAPI従量を社内で使い分けられますか？

使い分けられます。対話型のClaude CodeはTeamアカウントで利用し、CI/CDや自動処理はClaude PlatformのAPIキーで実行できます。ただし、環境変数にANTHROPIC_API_KEYがあるとClaude CodeはサブスクリプションよりAPIキーを優先するため、意図しない請求先へ計上されないよう、認証方式と実行環境を分けて管理してください。

研修費用に助成金は使えますか？

生成AI研修は人材開発支援助成金の対象となり得ます。ただし対象要件・申請可否は研修の形態や企業の状況によって異なるため、管轄労働局または社労士にご確認ください。TechWorkerの研修費用についてはお問い合わせください。
