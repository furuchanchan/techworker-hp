Copilot Chat BasicとMicrosoft 365 Copilot Premiumの研修を分ける

Microsoft 365 Copilot Chatと有償のMicrosoft 365 Copilotは、研修課題を分けます。利用できるデータとアプリ内機能の差を、公式レポートの対象から読み解きます。

同じ「Copilot」の研修でも、参加者が使える機能や参照できるデータが違えば、同じ演習はできません。教材を作る前に、契約と利用環境をそろえて確認します。まず、公式の利用レポートがどの製品・アプリを区別しているかを見ます。

公式レポートから、製品ごとの利用を区別する

レポートは、Copilot ChatとMicrosoft 365アプリ内の利用を分けて追うための入口です。研修でも、Web情報中心の課題と、組織データを使う課題を同じ手順にしません。

無償範囲と有償版の研修は、どこを分けますか？

データの参照範囲、利用するアプリ、管理者が確認するレポートを分けます。

同じ受講者でも、ライセンス有無で演習を分岐します。全員が同じ画面を見られる前提の講義は避け、到達目標を共通化します。

研修は、どんな手順で分けて設計しますか？

利用環境の確認、目的の分離、演習の分岐、効果測定の分離、研修後の導線の5つで進めます。

手順1　最初に利用環境を確認する

研修の前に、対象者のライセンス区分とテナントの設定を突合します。名称やプランは更新されるため、固定表に頼りません。

2026年8月時点のMicrosoft公式説明は、3つのライセンス区分を区別しています。

  • Copilot Chat (Basic)
  • Microsoft 365 Copilot (Basic)
  • Microsoft 365 Copilot (Premium)

Chat BasicとPremiumでは、次の3点が異なります。

  • 組織データへの接続範囲
  • Microsoft 365アプリ内の体験
  • 利用レポート

開催前に、テナント、対象ライセンス、管理設定、利用可能アプリを確認します。対象者一覧と実際のライセンスの割り当ても突合します。

手順2　研修の目的を二つに分ける

Copilot Chat (Basic)は、全社員の安全な生成AI利用を入口にします。

  • 演習は、公開情報の要約、文章のたたき台、論点整理、ファイルを明示的に渡した分析などです。
  • 入力禁止情報、根拠確認、共有前レビューを必須にします。

Microsoft 365 Copilot (Premium)は、アプリ内の業務の変化を扱います。

  • 実際の業務フローを単位にします。
  • 例は、Teams会議の振り返り、Outlookメール、Word初稿、PowerPoint構成、Excel分析です。
  • アクセス権限が結果へ反映されるため、研修前にSharePointやTeamsの過剰共有を確認します。

手順3　共通演習と分岐演習を設計する

最初の30分は共通にします。目的の明確化、入力データの分類、出力の検証、引用元の確認を扱います。その後に、利用環境で分岐します。

開催前の確認票は、参加者、ライセンス区分、使えるアプリ、参照できる資料、代替課題を一行にまとめます。当日にTeams要約を使えない人には、公開情報や添付ファイルを使う課題へ切り替えます。

  • Chat組：公開情報、添付ファイル、文章作成。
  • Copilot組：Teams、Outlook、Wordなどの実務シナリオ。
  • 管理者組：レポート、権限、利用ルール、問い合わせ対応。

受講者が自分の画面で実行できない演習は、デモで見せても定着しません。参加者一覧とライセンス一覧を突合し、代替演習を用意します。

手順4　効果測定も別系列にする

Microsoft公式のCopilot Chat usage reportは、次の指標を扱います。

  • アクティブユーザー数（active users）
  • プロンプト総数（total prompts）
  • 利用日数（active days）

特定日の活動は、通常48時間以内に反映されます。対象範囲やライセンス条件には、注意が必要です。

Microsoft 365 Copilot側は、アプリ内利用と導入効果を別レポートで見ます。両者のアクティブユーザー数は合算せず、次を分けます。

  • Chat：安全に使える社員割合、継続利用、対象業務。
  • Copilot：アプリ別利用、対象業務の時間・品質・手戻り。
  • 共通：入力事故、誤引用、相談件数、業務成果。

プロンプト数をROIに換算せず、業務成果は導入前の基準値と比較します。NIST AI RMFが示すように、人とAIの役割、評価方法、限界を文書化し、運用中も測定します。

手順5　研修後の導線を変える

  • Chat利用者：週次の活用テーマと、安全相談窓口を提供します。
  • Copilot利用者：対象アプリごとのテンプレート、権限課題の修正、業務部門のチャンピオンを設定します。
  • 管理者：レポートの定義と、改善アクションを渡します。

30日後に、Chatで利用が続かない場合は、課題設定を見直します。Copilotで利用はあるが成果が弱い場合は、業務プロセスを見直します。追加研修を、自動的な答えにしません。

研修の設計がうまくいかない例には、どんなものがありますか？

同じ講座を全員に配る、区分を読み替える、利用者数を合算する、の3つが代表例です。

  • 同じプロンプト講座を、両者へ配る。Chatの利用回数は増えても、アプリ内の業務変化につながらないことがあります。
  • 固定の比較表だけを資料に残す。名称とプランは更新されます。開催前に、テナントと対象ライセンスを確認します。
  • Basicの中間プランをPremiumに読み替える。対象者一覧と、実際のライセンスの割り当てを突合します。
  • 自分の画面で実行できない演習を、デモで済ませる。デモで見せても定着しません。代替演習を用意します。
  • ChatとCopilotのアクティブユーザー数を合算する。両者は目的が違います。別系列で見ます。
  • プロンプト数をROIに換算する。業務成果は、導入前の基準値と比較します。

Chat BasicとPremiumの研修は、何がどう違いますか？

目的、演習、事前確認、効果測定、研修後の導線のすべてを、Chat系とCopilot系で分けます。

次の一歩は、何から始めればよいですか？

対象者のライセンス区分、データ、業務、管理設定を確認し、演習を分けるところから始めます。

TechWorkerでは、対象者のライセンス区分、データ、業務、管理設定を確認します。そのうえで、3つの区分ごとに、演習・定着・効果測定を分けて設計します。

定着課題は、Microsoft Copilotが定着しない原因と対策を参照してください。

ROIは、Microsoft 365 CopilotのROI測定も参照してください。
