Copilot Chat BasicとMicrosoft 365 Copilot Premiumの研修を分ける【2026】

Copilot Chat BasicとMicrosoft 365 Copilot Premiumは、研修も効果測定も2系統に分けて設計します。
全社へのCopilot研修を設計する、担当者の方に向けた記事です。
利用環境の確認から、演習の分け方、効果測定、研修後の導線までが分かります。

Copilot Chat BasicとMicrosoft 365 Copilot Premiumの研修は、なぜ分けるのですか？

使える機能が人ごとに違うため、利用環境を確認し、目的別に演習と効果測定を分けます。

全社研修で「Copilot」とだけ説明すると、参加者ごとに使える機能が異なり、演習を再現できません。

本記事の比較対象は、次の2つです。

  • Copilot Chat (Basic)
  • Microsoft 365 Copilot (Premium)

現行体系には、Microsoft 365 Copilot (Basic)もあります。実際の研修では、3つのlicense区分を確認します。

  • Chat Basic：全社員の安全な生成AI利用の入口です。
  • Premium：アプリ内の業務変化を扱います。

目的が違うので、演習も効果測定も分けます。同じプロンプト講座を両者へ配ると、Chatの利用回数は増えても、アプリ内の業務変化につながらないことがあります。

研修は、どんな手順で分けて設計しますか？

利用環境の確認、目的の分離、演習の分岐、効果測定の分離、研修後の導線の5つで進めます。

手順1　最初に利用環境を確認する

研修の前に、対象者のライセンス区分とテナントの設定を突合します。名称やプランは更新されるため、固定表に頼りません。

2026年8月時点のMicrosoft公式説明は、3つのlicense区分を区別しています。

  • Copilot Chat (Basic)
  • Microsoft 365 Copilot (Basic)
  • Microsoft 365 Copilot (Premium)

Chat BasicとPremiumでは、次の3点が異なります。

  • 組織データへの接続範囲
  • Microsoft 365アプリ内の体験
  • 利用レポート

開催前に、テナント、対象ライセンス、管理設定、利用可能アプリを確認します。対象者一覧と実際のlicense assignmentも突合します。

手順2　研修の目的を二つに分ける

Copilot Chat (Basic)は、全社員の安全な生成AI利用を入口にします。

  • 演習は、公開情報の要約、文章のたたき台、論点整理、ファイルを明示的に渡した分析などです。
  • 入力禁止情報、根拠確認、共有前レビューを必須にします。

Microsoft 365 Copilot (Premium)は、アプリ内の業務の変化を扱います。

  • 実際の業務フローを単位にします。
  • 例は、Teams会議の振り返り、Outlookメール、Word初稿、PowerPoint構成、Excel分析です。
  • アクセス権限が結果へ反映されるため、研修前にSharePointやTeamsの過剰共有を確認します。

手順3　共通演習と分岐演習を設計する

最初の30分は共通にします。目的の明確化、入力データの分類、出力の検証、引用元の確認を扱います。その後に、利用環境で分岐します。

  • Chat組：公開情報、添付ファイル、文章作成。
  • Copilot組：Teams、Outlook、Wordなどの実務シナリオ。
  • 管理者組：レポート、権限、利用ルール、問い合わせ対応。

受講者が自分の画面で実行できない演習は、デモで見せても定着しません。参加者一覧とライセンス一覧を突合し、代替演習を用意します。

手順4　効果測定も別系列にする

Microsoft公式のCopilot Chat usage reportは、次の指標を扱います。

  • active users
  • total prompts
  • active days

特定日の活動は、通常48時間以内に反映されます。対象範囲やライセンス条件には、注意が必要です。

Microsoft 365 Copilot側は、アプリ内利用と導入効果を別レポートで見ます。両者のactive usersは合算せず、次を分けます。

  • Chat：安全に使える社員割合、継続利用、対象業務。
  • Copilot：アプリ別利用、対象業務の時間・品質・手戻り。
  • 共通：入力事故、誤引用、相談件数、業務成果。

プロンプト数をROIに換算せず、業務成果は導入前のbaselineと比較します。NIST AI RMFが示すように、人とAIの役割、評価方法、限界を文書化し、運用中も測定します。

手順5　研修後の導線を変える

  • Chat利用者：週次の活用テーマと、安全相談窓口を提供します。
  • Copilot利用者：対象アプリごとのテンプレート、権限課題の修正、業務部門のチャンピオンを設定します。
  • 管理者：レポートの定義と、改善アクションを渡します。

30日後に、Chatで利用が続かない場合は、課題設定を見直します。Copilotで利用はあるが成果が弱い場合は、業務プロセスを見直します。追加研修を、自動的な答えにしません。

研修の設計がうまくいかない例には、どんなものがありますか？

同じ講座を全員に配る、区分を読み替える、利用者数を合算する、の3つが代表例です。

  • 同じプロンプト講座を、両者へ配る。Chatの利用回数は増えても、アプリ内の業務変化につながらないことがあります。
  • 固定の比較表だけを資料に残す。名称とプランは更新されます。開催前に、テナントと対象ライセンスを確認します。
  • Basicの中間planをPremiumに読み替える。対象者一覧と、実際のlicense assignmentを突合します。
  • 自分の画面で実行できない演習を、デモで済ませる。デモで見せても定着しません。代替演習を用意します。
  • ChatとCopilotのactive usersを合算する。両者は目的が違います。別系列で見ます。
  • プロンプト数をROIに換算する。業務成果は、導入前のbaselineと比較します。

よくある質問

Copilot Chat BasicとMicrosoft 365 Copilot Premiumは研修を分けるべきですか？

分けるべきです。Chat Basicは安全な利用の入口、Premiumはアプリ内の業務変化が対象で、目的が違います。同じプロンプト講座を配ると、利用回数は増えても業務変化につながらないことがあります。

研修の前に何を確認しておくべきですか？

対象者のlicense区分、テナント、管理設定、利用可能なアプリです。参加者一覧と実際のlicense assignmentを突合し、自分の画面で実行できない演習には代替を用意します。

ChatとCopilotの利用状況は一つにまとめて見てよいですか？

まとめて見ません。両者のactive usersを合算せず、効果測定を別系列にします。Chatは安全に使える社員割合と継続利用、Copilotはアプリ別利用と業務の時間・品質・手戻りを見ます。

次の一歩は、何から始めればよいですか？

対象者のlicense区分、データ、業務、管理設定を確認し、演習を分けるところから始めます。

TechWorkerでは、対象者のlicense区分、データ、業務、管理設定を確認します。そのうえで、3つの区分ごとに、演習・定着・効果測定を分けて設計します。

定着課題は、Microsoft Copilotが定着しない原因と対策を参照してください。

ROIは、Microsoft 365 CopilotのROI測定も参照してください。
