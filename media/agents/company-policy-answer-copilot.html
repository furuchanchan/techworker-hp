社内規程に条文つきで答えるエージェント

社員から届く規程の質問に、SharePoint に置いた当社の規程だけを根拠にして答えます。どの回答にも規程名と条番号がつくので、社員はその場で原文を確かめられます。

01できること

これまで
  • 休暇や経費の決まりについて、同じ質問がメールや Teams で毎日のように届きます。
  • 担当者が規程集を開いて条文を探し、回答を書いて返しています。
  • 担当者によって、答え方や案内する条文が少しずつ違います。
  • 改定した規程が伝わらず、古い決まりのまま手続きされることがあります。
このエージェントを使うと
  • 社員は質問を書くだけで、結論と根拠の条文をその場で受け取れます。
  • 回答には規程名と条番号がつくので、社員も担当者も原文をすぐ確かめられます。
  • 規程の置き場所を SharePoint の1か所に決めるので、どの版が正しいかで迷わなくなります。
  • 担当者は規程に書いていない判断や例外の相談に時間を使えます。

02仕組み

エージェントが何を受け取り、何を見て、何を返すか。最後に人が確かめるところまでを1枚にしています。

受け取るもの

社員が書いた規程についての質問（例：時間単位の有給休暇は何時間まで取れますか）

エージェント

Microsoft 365 Copilot　エージェント ビルダー

指示文

役割と進め方、答え方を決める（04 指示文）

  • SharePoint の規程フォルダーにある就業規則と各種規程（Word または PDF）
  • 規程ごとの改定履歴の一覧
  • 総務の問い合わせ窓口と申請様式の案内

  • なし（つなぐ道具は使いません）

03作り方

  1. 1

    テンプレートから始める

    Microsoft 365 Copilot の左側のウィンドウで「新しいエージェント」を選びます。「テンプレートで開始」から「会社のポリシー」を選びます。説明と指示と推奨プロンプトが入った状態で編集が始まります。 Microsoft 365 Copilot ライセンス、または Copilot Studio の従量課金制（Copilot クレジット）を有効にしたテナントが要ります。SharePoint をナレッジにするには、このどちらかが必要です。従量課金制の場合は、課金ポリシーを SharePoint エージェント サービスに接続し、利用者を課金ポリシーに割り当てたセキュリティ グループに入れます。

  2. 2

    規程の置き場所を整える

    SharePoint に、規程だけを置いたフォルダーを1つ作ります。古い版は別のフォルダーへ移し、ファイル名に規程名と改定日を入れます。1つのエージェントで選べる SharePoint のファイルは100個までです。

  3. 3

    名前と指示を入れる

    「構成」タブを開き、「名前」に「規程案内（総務）」のような30文字以内の名前を入れます。「説明」には、誰が何を聞くためのエージェントかを短く書きます。「指示」にこのページの指示文を貼り、窓口名と内線番号を当社のものに書き換えます。

  4. 4

    ナレッジに規程フォルダーを入れる

    「ナレッジ」の欄で、手順2のフォルダーを参照して選ぶか、URL を貼ります。「指定したソースのみを使用する」をオンにします。追加した直後のファイルは「準備中」と表示され、準備が終わるまで回答に使われません。

  5. 5

    スターター プロンプトを決める

    「スターター プロンプト」に、社員がよく聞く質問を3〜5個入れます。たとえば、慶弔休暇の日数、出張の日当、在宅勤務の申請方法を入れます。

  6. 6

    「試してみる」で確かめる

    「試してみる」タブで、答えが分かっている質問を20問ほど聞きます。結論、条番号、引用が規程と合っているかを1問ずつ照らし合わせます。規程にない質問もして、窓口へ案内されるかを確かめます。

  7. 7

    作成して共有する

    「作成」を選ぶと、はじめは自分だけが使える状態で作られます。「共有」を選び、使う社員のグループを「チャット可能」で追加します。指示や資料を直したあとは、右上の「更新」を選ぶと利用者に反映されます。

04指示文（そのまま貼れます）

エージェント ビルダーの「構成」タブにある「指示」欄（8,000文字まで）に貼ります。［　］のところは自社の言葉に置き換えてください。

指示文 — Microsoft 365 Copilot エージェント ビルダー
# 役割
あなたは当社の総務部の規程案内係です。社員から届く社内規程の質問に、ナレッジにある当社の規程だけを根拠にして答えます。

# 受け取るもの
社員が書いた質問を1件受け取ります。休暇、勤務、経費、出張、備品、社内手続きについての質問が中心です。

# 進め方
1. 質問がどの規程に関係するかを考えます。
2. ナレッジの規程から、該当する条文を探します。
3. 条文が複数あるときは、それぞれ確かめます。改定日が新しい版を優先します。
4. 雇用区分や勤務地で答えが変わるときは、先に確認の質問を1つだけします。
5. 条文の内容を、職場でふだん使う言葉に言い換えて答えます。

# 答え方
- 最初に結論を1〜2文で書きます。
- 次に「根拠」として、規程名、条番号、項番号を示し、条文の該当部分を引用します。
- 手続きが要るときは、「手続き」として順番に書きます。申請先や様式名は、規程に書いてあるとおりに示します。
- 最後に「確認先」として、総務部の窓口（内線〇〇〇〇）を案内します。
- 文末は「です」「ます」にし、1つの文に1つのことだけを書きます。

# 根拠の示し方
- どの回答にも、根拠にした規程名と条番号を示します。
- 引用は条文の文言を変えずに示します。
- 言い換えた説明と条文の引用は、分けて書きます。

# わからないときの返し方
- ナレッジに該当する条文がないときは、推測で答えません。「該当する規程が見つかりませんでした。総務部（内線〇〇〇〇）にお問い合わせください。」と返します。
- 条文の読み方が分かれそうなときは、条文を示したうえで「解釈は総務部の担当者が判断します」と書き添えます。

# させないこと
- 一般常識、他社の例、法律の一般論で答えを補いません。
- 人事評価、懲戒、給与の額、休職の可否のように、個人の判断が関わる質問には答えず、担当者へ案内します。
- 社員の個人情報を聞き出しません。
- 規程の改定案を示したり、例外を約束したりしません。

05管理者が先に決めること

使い始める前に、Microsoft 365 Copilot の管理者が決めておく設定です。ここを決めてから配ると、情報の扱いで止まりにくくなります。

ナレッジにする SharePoint サイトとフォルダーのアクセス許可

エージェントは SharePoint の既存のアクセス許可と秘密度ラベルに従って答えます。規程を全社員が読める場所に置かないと、読めない社員には答えが返りません。人事の内部資料が同じ場所にあると、読める人の回答に混ざるおそれがあります。

制限付き SharePoint 検索の設定

制限付き SharePoint 検索が有効なテナントでは、SharePoint をナレッジに使えません。作り始める前に、SharePoint の管理者と設定を確かめます。

エージェントを組織全体へ共有できる人

Microsoft 365 管理センターでは、組織全体への共有を「すべてのユーザー」「特定のユーザーまたはグループ」「ユーザーなし」から選べます。総務が作ったエージェントを誰が全社に公開できるかを、先に決めておきます。

端末からアップロードするファイルの扱い

端末からアップロードしたファイルの内容は、エージェントを使える人全員が回答として見られます。Microsoft Purview 情報バリアも効きません。規程は SharePoint に置き、アップロードは使わない決まりにします。

やり取りの記録を確かめる人

社員とエージェントのやり取りは、Microsoft Purview ポータルの「監査」で CopilotInteraction として記録されます。記録には回答のために参照したファイルも含まれます。誰が記録を確かめるかを、情報システム部門と決めておきます。

06人が確かめるところ

  • 回答の根拠にされた条文が最新の版かどうかを、総務の担当者が月に1回抜き出して確かめます。
  • 規程にない例外や、個人の事情が関わる判断はエージェントに任せず、担当者が決めます。
  • 規程を改定したら、古い版を規程フォルダーから外し、よく聞かれる質問を「試してみる」で聞き直します。

07うまくいかないとき

規程に書いていない一般論で答えてしまう

「指定したソースのみを使用する」は、ナレッジを優先させる設定です。一般的な AI の知識による回答が残ることがあります。指示文の「させないこと」を残し、規程にないときの返し方を指示に書いておきます。

古い版の規程を引用する

規程フォルダーに旧版が残っていないかを確かめます。旧版は別のフォルダーへ移し、ファイル名に改定日を入れます。

一度に2つ以上聞くと、片方の答えが抜ける

このテンプレートは一度に1つの質問に答える作りです。スターター プロンプトの説明に「1回に1つずつ聞いてください」と書いておきます。

追加したばかりの規程が回答に出てこない

「構成」タブの「ナレッジ」で、ファイルが「準備中」になっていないかを見ます。数分待ってから、ナレッジ欄の上にある更新ボタンで状態を読み込み直します。

0830日後に測ること

使われているか、どれだけ時間が浮いたか、出来は十分か。使い始めて30日後に、次の点を確かめます。

使われているか：このエージェントのアクティブ ユーザー数

Microsoft 365 管理センターの「レポート」から「使用状況」を開き、「Microsoft Copilot」の「エージェント」を選びます。このエージェントの「アクティブ ユーザー」と「ユーザーに送信された応答」を見ます。対象の社員数と並べて、使っていない部署を探します。

時間：総務に直接届く規程の質問の件数

使い始める前の2週間と、30日後の2週間で、総務の共有メールボックスと Teams に届いた規程の質問を数えます。担当者が1件の回答に使った時間も10件ほど記録し、前後で比べます。

出来：結論と条番号がそろって正しい回答の数

答えが分かっている質問を20問用意し、30日後にもう一度聞きます。結論、規程名、条番号の3点がすべて合っている回答を数えます。外れた質問は規程の置き方と指示文のどちらを直すかを書き残します。

09広げ方

  • 情報システム部門がパソコンやアカウントの決まりに答える版
  • 経理が経費精算のルールと勘定科目の選び方に答える版
  • 入社したばかりの社員に、最初の3か月に必要な手続きを案内する版
