役員会の前に論点を1枚にまとめるエージェント

役員会の議題と資料を指定すると、決めること、背景の事実、選択肢、想定される質問を A4 1枚分の下書きにまとめます。資料にない点は足りない情報として示します。

01できること

これまで
  • 経営企画の担当者が各部の資料とメールを読み込んで論点の整理表を作っています。
  • 資料ごとに書き方が違い、役員が会議で何を決めるのかをつかみにくくなっています。
  • 前回の役員会で出た宿題が、次の資料に引き継がれないことがあります。
このエージェントを使うと
  • 議題と資料を指定すると、決めることと背景の事実が並んだ下書きが出てきます。
  • 資料にない数字や事実は「足りない情報」として示されるので、担当部署への確認をすぐ始められます。
  • 前回の会議の記録を読ませると、宿題の進み具合も下書きに入ります。
  • 担当者は事実の確認と推奨の書き方に時間を使えます。

02仕組み

エージェントが何を受け取り、何を見て、何を返すか。最後に人が確かめるところまでを1枚にしています。

受け取るもの

会議名、開催日、議題（1回に1つ）、出席する役員の役職、読ませたい資料と会議の名前

エージェント

Microsoft 365 Copilot　エージェント ビルダー

指示文

役割と進め方、答え方を決める（04 指示文）

渡す資料
  • SharePoint の役員会フォルダーにある提案資料と議事録
  • 前回の役員会の Teams 会議（記録とトランスクリプト）
  • 議題に関係する指定の Teams チャット
つなぐ道具
  • なし（つなぐ道具は使いません）
返すもの

A4 1枚分の論点メモの下書き（決めること、背景、選択肢、担当部署の推奨、想定される質問、前回からの宿題、足りない情報）

人が確かめる

推奨案の中身と、役員に渡す最終版は、経営企画の責任者が決めます。

03作り方

  1. 1

    テンプレートから始める

    Microsoft 365 Copilot の左側のウィンドウで「新しいエージェント」を選びます。「テンプレートで開始」から「エグゼクティブ ブリーフィング エージェント」を選びます。このテンプレートは会議前のブリーフィングと会議後の概要を作る作りになっています。 Microsoft 365 Copilot ライセンスが要ります。メール、Teams のチャット、Teams の会議をナレッジにできるのは、このライセンスを持つ利用者だけです。Copilot Studio の従量課金制だけのテナントでは、メールと Teams をナレッジに使えません。

  2. 2

    名前と指示を入れる

    「構成」タブを開き、「名前」に「役員会 論点メモ」のような30文字以内の名前を入れます。「指示」にこのページの指示文を貼ります。見出しの並びは当社の役員会資料の書式に合わせて直します。

  3. 3

    役員会フォルダーをナレッジに入れる

    「ナレッジ」の欄で、SharePoint の役員会フォルダーを参照して選びます。1つのエージェントで選べる SharePoint のファイルは100個までです。古い年度の資料は別のフォルダーへ移しておきます。

  4. 4

    Teams の会議とチャットは1つずつ選ぶ

    「ナレッジ」の検索バーを選び、「会議」タブから前回の役員会を選びます。関係するチャットは「チャット」タブから5つまで選べます。「お気に入りの Teams チャットと会議」を選ぶと、すべての会議の記録と予定表全体が対象になるので避けます。

  5. 5

    使う情報の範囲を絞る

    「指定したソースのみを使用する」をオンにします。社外の Web の情報を混ぜないよう、「すべての Web サイトの検索」はオフにします。

  6. 6

    「試してみる」で過去の役員会を再現する

    「試してみる」タブで、前回の議題と資料を指定して下書きを作らせます。数字が資料と合っているかを1つずつ確かめます。資料にない事実が混ざっていないかも確かめます。

  7. 7

    作成して経営企画の中で共有する

    「作成」を選んだあと、「共有」を開きます。経営企画のメンバーを1人ずつ追加します。「チャット アクセスの組織全体で共有する」はオンにしません。

04指示文（そのまま貼れます）

エージェント ビルダーの「構成」タブにある「指示」欄（8,000文字まで）に貼ります。［　］のところは自社の言葉に置き換えてください。

指示文 — Microsoft 365 Copilot エージェント ビルダー
# 役割
あなたは当社の経営企画部で、役員会の準備を手伝う担当です。議題ごとに、役員が会議の前に読む論点メモの下書きを作ります。

# 受け取るもの
- 会議名と開催日
- 議題（1回に1つ）
- 出席する役員の役職
- 読んでほしい資料と会議の名前（ナレッジにある SharePoint の資料、Teams の会議）

# 進め方
1. 指定された資料と会議の記録から、議題に関係する事実を集めます。
2. 集めた事実を、決めること、背景、選択肢の順に整理します。
3. 前回の役員会で出た宿題があれば、その進み具合を確かめます。
4. 資料からわからない点を、「足りない情報」として書き出します。
5. A4 1枚分（1,200字ほど）に収まるよう、重要な順に並べます。

# 答え方
次の見出しで書きます。
1. 決めること：この議題で役員に決めてほしいことを1文で書きます。
2. 背景：判断に要る事実を3〜5個、箇条書きで書きます。
3. 選択肢：資料に出ている案を並べ、それぞれの利点と懸念を1行ずつ書きます。
4. 担当部署の推奨：資料に書かれている推奨だけを書きます。
5. 想定される質問：役員から出そうな質問と、答えの材料になる資料の箇所を書きます。
6. 前回からの宿題：担当者と進み具合を書きます。
7. 足りない情報：誰に何を確かめればよいかを書きます。
文末は「です」「ます」にし、1つの文に1つのことだけを書きます。

# 根拠の示し方
- 数字と事実には、資料名とページ、または会議名と日付を添えます。
- 資料に書いてある事実と、あなたが整理した要約は、分けて書きます。

# わからないときの返し方
- 資料に根拠がない見出しは空けておき、「資料に記載なし」と書きます。
- 資料どうしで数字が食い違うときは、両方を出典つきで並べ、「確認が必要」と書きます。

# させないこと
- 資料にない数字、日付、固有名詞を作りません。
- あなた自身の推奨や賛否を書きません。
- 役員の発言や考えを推し量って書きません。
- 個人の人事評価や処遇についての記述は、資料にあっても要約に入れません。その箇所には「人事案件のため省略」と書きます。
- 社外の Web の情報を使いません。

05管理者が先に決めること

使い始める前に、Microsoft 365 Copilot の管理者が決めておく設定です。ここを決めてから配ると、情報の扱いで止まりにくくなります。

ライセンスを割り当てる利用者

メール、Teams のチャット、Teams の会議をナレッジにするには、利用者に Microsoft 365 Copilot ライセンスが要ります。経営企画と役員秘書のうち誰が使うかを決め、ライセンスを割り当てます。

メールをナレッジに入れるかどうか

メールは範囲を指定できず、追加するとメールボックス全体がナレッジになります。共有した相手は作成者のメールをナレッジとして使えません。役員会に関係のないメールが混ざらないよう、はじめは SharePoint と指定の会議だけで始めます。

共有の範囲と資料のアクセス許可

エージェントは利用者ごとの SharePoint のアクセス許可に従って答えます。共有ダイアログで経営企画のメンバーだけを追加し、組織全体への共有はしません。役員会フォルダーのアクセス許可も、同じメンバーに合わせて見直します。

秘密度ラベル

エージェントの回答には、参照した資料のうち最も優先度の高い秘密度ラベルが適用されます。役員会フォルダーの資料に当社の機密区分のラベルを付けておくと、下書きにも同じ扱いが引き継がれます。

Web 検索が使われたかの記録

Microsoft Purview の監査ログでは、Copilot が Web を検索したやり取りを、AISystemPlugin.Id の BingWebSearch という値で見分けられます。情報システム部門がこの記録を定期的に確かめる、と決めておきます。

06人が確かめるところ

  • 下書きの数字は、経営企画の担当者が元の資料と1つずつ照らし合わせます。
  • 推奨案の中身は担当部署と経営企画の責任者が決め、エージェントには決めさせません。
  • 役員の発言や意向を推し量って書いた部分がないかを、役員に渡す前に読み直します。

07うまくいかないとき

関係のない会議やメールの内容が混ざる

「お気に入りの Teams チャットと会議」や「マイ メール」をナレッジから外します。前回の役員会など、必要な会議だけを1つずつ選び直します。

資料にない数字が下書きに出てくる

指示文の「させないこと」に、資料にない数字を書かない決まりを残します。数字には資料名を添えるよう指示しておくと、出典のない数字を見つけやすくなります。

長い会議の記録が読まれていない

過去のトランスクリプトの大きさによっては、すべての記録を読めないことがあります。議事録を Word にまとめて役員会フォルダーに置き、そちらを読ませます。

議題をまとめて頼むと、後半の議題が薄くなる

このテンプレートは一度に1つの質問に答える作りです。議題ごとに1回ずつ頼みます。

0830日後に測ること

使われているか、どれだけ時間が浮いたか、出来は十分か。使い始めて30日後に、次の点を確かめます。

使われているか：役員会のたびに使われたか

30日間に開いた役員会と経営会議の議題の数と、このエージェントで下書きを作った議題の数を、経営企画の作業記録で比べます。Microsoft 365 管理センターのエージェントの使用状況レポートで、アクティブ ユーザー数も見ます。

時間：論点メモを役員に送るまでの時間

資料がそろってから論点メモを役員に送るまでの時間を記録します。使い始める前の3回と、使い始めた後の3回で比べます。

出来：役員からの差し戻しと確認の質問の数

論点メモを送ったあとに役員から届いた確認の質問と、書き直しの依頼を数えます。差し戻しの理由を「事実の誤り」「論点の不足」「書き方」に分けて記録します。

09広げ方

  • 役員会のあとに、決まったこと、宿題、担当者を一覧にする版
  • 取引先の経営者と会う前に、これまでのやり取りと論点を整理する版
  • 株主総会や社内説明会で聞かれそうな質問と答えの材料をまとめる版
