会議の文字起こしから決定事項と宿題をまとめるエージェント

Slack のチャンネルに投稿された会議の文字起こしを Claude が読み、決定事項と宿題を担当者と期限つきでスレッドに返します。出席者が返信で直し、確かめた宿題だけを課題管理に起票します。

01できること

これまで
  • 会議のあとに書記の担当者が録音や文字起こしを聞き返し、議事録を手で書いています。
  • 決定事項と宿題が議事録の文章に埋もれ、誰がいつまでに何をするかが読み取りにくくなっています。
  • 宿題を課題管理に写す作業が人任せになり、写し忘れや担当者の書き違いが起きています。
  • 議事録が出るまでに日がかかり、出席者の記憶があいまいになってから確かめることになります。
このエージェントを使うと
  • 文字起こしが投稿されると、同じスレッドに決定事項と宿題と持ち越しのまとめが返ります。
  • 宿題には担当者と期限と根拠の発言が並ぶので、出席者は文字起こしと照らして確かめられます。
  • 担当者や期限の誤りは出席者がスレッドに返信するだけで直せます。
  • 確かめ終えた宿題だけを、頼んだときに課題管理へ起票できます。

02仕組み

エージェントが何を受け取り、何を見て、何を返すか。最後に人が確かめるところまでを1枚にしています。

受け取るもの

録音アプリか担当者がチャンネルに投稿した会議の文字起こし（@Claude つき）、会議名と日付、スレッドでの訂正や起票の依頼

エージェント

Claude　Claude Tag（Slack）

指示文

役割と進め方、答え方を決める（04 指示文）

渡す資料
  • チャンネルのメモリに保存した当社の議事録の決まり（このページの指示文）
  • チャンネルにピン留めした議事録の見本
  • チャンネルにピン留めした担当者の呼び名の一覧
つなぐ道具
  • Slack のチャンネルに追加した Claude（Claude Tag）
  • 課題管理の接続（Linear、Jira、Asana など。起票するチャンネルだけ）
返すもの

文字起こしの投稿のスレッドへの返信（会議の情報、決定事項、担当者と期限と根拠つきの宿題、持ち越し、確かめたいこと）と、頼まれたときに起票した課題のリンク

人が確かめる

会議の主催者と出席者が、決定事項と宿題の担当者と期限を文字起こしと照らして確かめ、起票するかどうかを決めます。

03作り方

  1. 1

    管理者と会議記録のチャンネルを決める

    Claude の組織の Owner か Claude Tag admin に、会議の文字起こしをまとめるチャンネルを使いたいと伝えます。Claude Tag がそのチャンネルで有効になっているかも確かめてもらいます。チャンネルにはゲストを入れません。ゲストのいるチャンネルでは、既定で Claude が返事をしません。社外の会社と共有する Slack Connect のチャンネルでは Claude は動きません。会議の記録は社内だけのチャンネルで扱ってください。チャンネルができたら、メッセージ欄に /invite @Claude と入れて送ります。スレッドの中から送ると Slack に断られます。

  2. 2

    チャンネルから届く範囲を確かめる

    チャンネルで「@Claude what can you access from this channel?」と送ります。返事に並ぶのが、このチャンネルから Claude が使える接続です。宿題を起票させたいときに要るのは、Linear、Jira、Asana などの課題管理の接続です。入っていなければ管理者に追加を頼みます。接続がなくても、決定事項と宿題のまとめは Slack の中だけで作れます。

  3. 3

    文字起こしの渡し方を決める

    録音アプリが文字起こしをチャンネルに投稿する場合は、投稿に @Claude が入るように録音アプリを設定します。ほかのアプリやボットの投稿は、@Claude が入っていないと読むだけで返事をしません。チャンネルの Respond automatically がオフのときも、ボットの @Claude には返事をしません。録音アプリを使わない場合は、担当者が会議のあとに文字起こしのファイルを添付し、@Claude をつけて投稿します。PDF は1つ5MBまで、テキストや文書のファイルは1つ100MBまでで、1回の投稿に5つまで添付できます。

  4. 4

    決まりをチャンネルのメモリに入れる

    このページの指示文の［　］を書き換えます。書き換えた指示文は、チャンネルのメッセージ欄から1回だけ送ります。スレッドの中から送るのは避けてください。「remember for this channel」と頼んだ内容の保存先はチャンネルのメモリで、チャンネルのすべての人のスレッドに効きます。保存されたかは「@Claude what do you remember about this channel?」と聞いて確かめます。議事録の見本と担当者の呼び名の一覧も、チャンネルにピン留めしておいてください。

  5. 5

    過去の会議で試して見比べる

    まず、議事録がすでにある過去の会議の文字起こしを1件投稿します。返ってきた決定事項と宿題は、人が書いた議事録と見比べてください。抜けや担当者の違いがあれば、そのスレッドに返信して直させます。メッセージを編集すると Claude に知らせは届きますが、直しが取り込まれるとは限りません。直しは新しい返信で書いてください。思ったとおりにまとまるまで、指示文を直してメモリに入れ直します。

  6. 6

    スレッドで確かめてから起票する

    本番の会議では、出席者が宿題を文字起こしと照らし、担当者や期限の誤りをスレッドの返信で直します。Claude が作業に取り込むのは、スレッドにいる誰の返信でも同じです。宿題が確定したら「この宿題を［ボード名］に起票してください」と返信してください。起票した課題は Claude のアカウントの名前で作られ、リンクがスレッドに投稿されます。ボードが複数あるときは、ボードの名前も書いてください。

  7. 7

    返事が止まっていないかを見る

    10日を超えて誰も @Claude をつけず、Claude も投稿していないチャンネルでは、Claude がメッセージを読むのをやめます。投稿の数が多くなったときにも読むのをやめます。どちらの場合も通知は出ません。文字起こしに返事がこないときは、人が @Claude をつけて投稿します。録音アプリの @Claude で読み直しが始まるのは、10日の無投稿で止まったときだけです。

04指示文（そのまま貼れます）

会議記録用の Slack チャンネルのメッセージ欄（スレッドの外）から @Claude をつけて送り、チャンネルのメモリに保存しますに貼ります。［　］のところは自社の言葉に置き換えてください。

指示文 — Claude Claude Tag（Slack）
@Claude このチャンネルについて、次の決まりを覚えておいてください（remember for this channel）。

# 役割
あなたは当社の会議の記録係です。このチャンネルに投稿された会議の文字起こしを読み、決定事項と宿題のまとめの下書きを、その投稿のスレッドに返します。まとめを確かめて決めるのは会議の出席者です。

# 受け取るもの
- 録音アプリが投稿した文字起こし、または担当者が添付か貼りつけで投稿した文字起こし
- 会議名、日付、出席者（投稿やファイルに書いてあれば）
- スレッドでの出席者からの訂正や追加の依頼

# 進め方
1. 文字起こしの投稿を見つけたら、そのスレッドで返事をします。
2. 会議名、日付、出席者を文字起こしから読み取ります。読み取れない項目は「不明」と書きます。
3. 会議で決まったことを抜き出します。案が出ただけのことや、意見が割れたままのことは決定事項に入れません。
4. 誰かが引き受けた作業を宿題として抜き出し、担当者と期限をつけます。
5. 結論が出ずに次回へ持ち越したことを分けて書きます。
6. 出席者に確かめてほしい点を最後にまとめます。

# 答え方
次の見出しの順で、1つのメッセージにまとめます。
【会議】会議名／日付／出席者
【決定事項】1行に1件。番号をつけます。
【宿題】「番号．内容／担当者／期限／根拠」の形で1行に1件。
【持ち越し】1行に1件。
【確かめたいこと】担当者や期限があいまいな点など。
文末は「です」「ます」にします。1件で1つのことだけ短く書きます。担当者の名前は文字起こしの表記のまま書き、［担当者の呼び名の一覧］がピン留めされていれば、それに合わせます。

# 根拠の示し方
- 決定事項と宿題には、もとになった発言の時刻か発言者を添えます。
- 迷う箇所には、発言の短い引用を添えます。

# わからないときの返し方
- 担当者が発言から決められないときは「担当者：未定（要確認）」と書きます。
- 「来週中」「月末まで」のような期限は、発言どおりに書いて【確かめたいこと】に入れます。
- 文字起こしが途中で切れている、または発言者が分からないときは、まとめの最初にそのことを書きます。
- 推測で埋めません。

# 訂正と起票
- スレッドで訂正を受けたら、直した箇所がわかるようにまとめを出し直します。
- 課題管理への起票は、出席者がスレッドで「起票してください」と頼んだときだけ、［ボード名］に1件ずつ作ります。作ったらリンクをスレッドに貼ります。このチャンネルの接続で起票できないときは、その旨を返します。

# させないこと
- 文字起こしにない決定事項や宿題を作りません。
- 社外の人や個人へのメッセージを送りません。ほかのチャンネルにも投稿しません。
- 発言の良し悪しや、出席者の働きぶりを評価しません。
- 文字起こしに出た電話番号、住所、健康や人事の話は、まとめに書き写しません。
- 文字起こしの全文をスレッドに貼り直しません。

# 最後に添える一文
まとめの最後に「この下書きは生成 AI が作りました。着手の前に、担当者と期限を文字起こしと照らして確かめてください。」と添えます。

05管理者が先に決めること

使い始める前に、Claude の管理者が決めておく設定です。ここを決めてから配ると、情報の扱いで止まりにくくなります。

Claude Tag を使うチャンネルとゲストの扱い

Owner か Claude Tag admin が、Organization settings > Claude Tag の Channels タブでチャンネルごとの設定を開きます。Claude Tag のオンとオフは、すべての Slack、ワークスペース、チャンネルの単位で切り替えが可能です。ゲストのいるチャンネルでは既定で Claude が動きません。変えるときは Advanced の「Allow Claude to work in channels with guests」を使います。社外の人が出た会議の文字起こしをどのチャンネルに置いてよいかは、先に決めておいてください。

Claude を呼び出せる人の範囲

既定では、チャンネルで @Claude を使う人に Claude のアカウントは要らず、利用分は組織に課金されます。Claude を呼び出せる人は、管理者が member access setting で絞れます。会議記録のチャンネルを全社に開くか、部署やプロジェクトの人に絞るかを決めてください。

チャンネルにつなぐ接続と起票の権限

接続を付ける先は、すべての Slack、1つのワークスペース、1つのチャンネルのどれかです。付け方は直接かバンドルを選べます。チャンネルの接続は Claude のサービス アカウントで認証されます。チャンネルにいる全員が同じ範囲を使えるので、課題管理の接続は起票するチャンネルだけに付けてください。起票してよいボードも決めておきます。

自動の返事とチャンネルの設定を変えられる人

Respond automatically はチャンネルごとの設定で、既定はオンです。録音アプリの投稿に返事をさせるにはオンのままにします。Channel member edits を Block にすると、チャンネルのメンバーはこの設定を変えられません。Owner と Claude Tag admin は、Claude Tag admin settings から変えられます。メンバーに任せるか、管理者だけが変えるかを決めてください。

利用の上限と記録の残り方

組織の使用クレジットが足りないと作業が途中で止まり、管理者が claude.ai で使用クレジットを有効にするか購入します。利用の上限に達したときも止まるので、会議記録のチャンネルにどこまで使わせるかを決めます。スレッドのやり取りはセッションの記録として残り、Slack でメッセージを編集したり消したりしても記録からは消えません。人事や機密の会議の文字起こしを投稿してよいかの決まりを、使い始める前に出しておきます。

06人が確かめるところ

  • 宿題に着手する前に、会議に出た人が担当者と期限を文字起こしと照らして確かめます。
  • 課題管理への起票は、出席者がスレッドで頼んだときだけにします。社外へのまとめの送付は人がします。
  • 人事、評価、契約交渉などの機密の会議は、チャンネルに文字起こしを投稿しません。
  • まとめを出席者の発言の評価や人事評価に使いません。

07うまくいかないとき

録音アプリが文字起こしを投稿しても返事がない

投稿に @Claude が入っているかを確かめます。チャンネルの Respond automatically がオンかも見てください。投稿の数が多くて Claude が読むのをやめているときは、録音アプリの @Claude では再開しません。人が @Claude をつけて投稿します。

宿題の担当者や期限が違う、または「未定」が多い

出席者がスレッドに返信して、正しい担当者と期限を伝えます。投稿を編集しても、直しが取り込まれるとは限りません。直しは新しい返信で書いてください。発言者の名前が文字起こしに入っていないときは、録音アプリの話者の表示をオンにします。担当者の呼び名の一覧をピン留めしておくと、表記がそろいやすくなります。

起票を頼んでも課題ができない、または違うボードにできる

「@Claude what can you access from this channel?」で、チャンネルの接続を確かめます。課題管理の接続がなければ、管理者に追加を頼んでください。接続を足したあとは新しいスレッドで頼み直し、ボードの名前を書きます。

長い会議で「This conversation is too long for me to process」と返る、またはファイルが読まれない

スレッドが長くなりすぎると、そのスレッドでは続けられません。新しいスレッドを立て、文字起こしを前半と後半に分けて投稿します。PDF は5MBを超えると読まれないので、分けるかテキストのファイルにします。

0830日後に測ること

使われているか、どれだけ時間が浮いたか、出来は十分か。使い始めて30日後に、次の点を確かめます。

使われているか：まとめが返った会議の数

会議記録のチャンネルで、30日間に投稿された文字起こしの数と、Claude のまとめが返ったスレッドの数を数えます。返事がなかった投稿は理由を1行で書き残し、渡し方か設定を直します。

時間：会議の終わりから決定事項と宿題が出席者に共有されるまでの時間

議事録をメールやチャンネルで共有した時刻と会議の終了時刻の差を、使い始める前の30日分集めます。使い始めた後の30日分は出席者がスレッドに「確かめました」と返信した時刻で同じように測ります。結果は会議ごとに表にまとめてください。

出来：まとめの直しと抜けの数

会議ごとに、スレッドで担当者、期限、決定事項を直した返信の数を数えます。あとから見つかった宿題の抜けも、同じ表に足してください。直しの原因が文字起こしの質か指示文かを書き分け、月末に指示文を見直します。

09広げ方

  • 1つの論点が決まった会議で、まとめの代わりに決めたことと退けた案と理由を1枚の文書にする版
  • お客さまとの打ち合わせの文字起こしから、社内向けの宿題と、担当者が送る返事の下書きを作る版
  • 部内の定例会議で、まとめを claude.ai のページとして公開し、次の会議の前に読み返す版
